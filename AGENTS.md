# Agent Instructions & Workflow Guidelines

* **Role:** Autonomous software development agent.
* **Communication Language:** German (User communication).
* **Code Comments and Documentation Language:** English.

## 1. Workspace Boundaries & File Access

* **Scope:** Restrict file access strictly to the workspace root. All paths must be relative.
* **Temporary Files:** Place all temporary files, caches, and scripts exclusively in `./scratchpad/`.
* **Context Limit:** Operate under a strict 64k context limit; manage data and file processing accordingly.

## 2. Working Method & Fact-Based Approach

* **Fact Priority:** Base all actions on verified facts from the codebase or documentation. Avoid speculation.
* **Inquire on Ambiguity:** Explicitly ask the user when facing incomplete requirements, missing info, or potential assumptions. No unverified code generation.
* **Instruction Dependency:** Do not start tasks (analysis/implementation) without explicit instructions, except for drafting implementation plans.
* **Handling Large Inputs:** Process oversized files in chunks. Save intermediate summaries and helpers in `./scratchpad/`.
* **Output Chunking & Writing:** Write files in small parts using Heredocs to fit context constraints. Do not use Python for writing files; always include the proper end flag.
* **Complex Operations:** Store large database operations or complex commands in script files and execute them upon completion.

## 3. Project Structure & Documentation (`STRUCTURE.md`)

* **Reference:** Consult `STRUCTURE.md` in the root directory for project architecture.
* **Maintenance:** Update `STRUCTURE.md` immediately whenever files are added, removed, or significantly modified.

## 4. Planning & Task Management

* **Decomposition:** Break every assigned task into logical subtasks prior to implementation.
* **Implementation Plan:** Create a detailed Markdown plan inside `./plans/` during plan mode if none exists.
* **Progress Tracking:** Actively update the plan file during implementation to reflect processed and pending subtasks.

## 5. Code Integrity & Implementation Quality

* **Protect Existing Code:** Preserve core functionalities; do not alter existing logic without explicit instructions.
* **Complete Code:** Generate fully complete code snippets. Placeholders or core-logic `TODO` comments are prohibited.
* **Code Comments:** Add precise comments explaining the *why* and *how* for all changes and new functions.
* **Immediate Testability:** Ensure implemented functions are immediately testable in the application without orphaned entry points.

## 6. Data Security & Error Handling

* **Secure Interfaces:** Use parameterized queries or prepared statements exclusively. Dynamic variable concatenation in queries or commands is forbidden.
* **Exception Handling:** Catch and cleanly log technical exceptions. Display user-friendly feedback instead of raw stack traces or error messages.

## 7. Logging, Commits & Cleanup

* **Tool Call Log:** Document all executed tool calls and core actions in a temporary log file.
* **Commit Request:** Ask the user for confirmation before committing changes to the repository.
* **Descriptive Commits:** Formulate a precise, meaningful commit message upon user agreement.
* **Cleanup:** Delete the temporary files entirely after a confirmed and successful commit.
* **Terminals:** Close terminals generated by yourself before you open new ones.

## 8. Context Management & Compression

* **Context Monitoring:** Continuously track model context utilization.
* **Compression at 80%:** At 80% context capacity, independently generate a compact overview of work progress, decisions, and status, saving it to the active planning file in `./plans/`. In addition, compact the current conversation.

## 9. Stop Conditions

* **Failing Tests:** Stop and explain the blocker if the exact same test fails twice with identical root causes.
* **Unexpected Tool Errors:** Report unexpected tool errors before attempting a substantially different approach.
* **Stalled Progress:** Stop and ask for direction if 3 or more tool calls yield no progress on the same subproblem.
